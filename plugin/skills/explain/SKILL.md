# 投资讲解

帮助读者理解已有投资成果，而不是替原作者继续形成投资判断。完成价值在于读者看清判断的依据与推断、重要分歧在哪里、条件变化怎样影响判断或选择，不只是把文字缩短或排得漂亮。

从用户本次的理解困难、用途和已知背景出发，读懂所承接的成果及解释它所需的依据。确定真正需要讲清的问题，不把局部疑问扩成整份研究的重讲，也不要求读者先提供完整画像。当前没有可承接成果时，请用户指定材料；需要形成新判断的任务由相应分析能力承担。

运用解释判断力，自主选择结构、篇幅、节奏和表达方式。可以解释术语、重排内容、合并冗余、展开原稿已有的意思，让支持与削弱、因果与条件、不同期限或选择之间的关系显露出来。根据理解难点选择文字、对照、时间线或关系图等手段；简单问题可以直接说清，不预设固定栏目、统一决策树或每次必须画图。

保持原成果的性质、判断强度、期限、条件、重要分歧与证据关系，以及分析、建议和用户决定的归属。突出原成果真正重要的判断和依据，把关键限制放在它所影响的主张附近，合并反复出现却没有增加含义的限定。原稿未形成主路径时，不替它选定一条；相关性不画成因果，条件推演不画成必然结果，视觉上的主次也不应制造原稿没有的确信。保留必要的来源入口，便于读者回查。

区分事件发生的概率与对判断依据的把握程度。原成果只有定性倾向时，保留其含义，不换算成数值概率；分支没有相应依据时，不为图形完整而补概率或凑成百分之百。解释缺失信息具体影响什么，不让笼统的不确定性遮住仍能成立的认识。

需要澄清原意、补充事实、解决实质矛盾或改变专业判断时，指出具体问题及其影响，交回承担原分析的能力或用户处理；可以先讲清已经能够解释的部分。不得用更流畅的表达掩盖论证缺口，也不借讲解新增投资建议。

默认直接在对话中使用普通 Markdown；需要关系图时优先采用放在代码块中的纯文本图，控制宽度和层次，使其在窄屏与纯文本环境中仍可读。只有确认宿主支持、且确实改善理解时才使用增强图形，并保留不依赖渲染的核心解释；不定义专用 Markdown 方言，也不以展示形式为交付目标。

无需为了讲解新建 case 或生成文件。需要保存或交付独立文档时，遵循[工作区约定](../../WORKSPACE.md)，沿用所承接成果的位置，保留原成果及其语境。用户需要独立可读的 HTML 成稿时，可使用 [report](../report/SKILL.md)；讲解不是研究、建议或成稿的必经步骤，各能力仍对自己的基本可读性负责。

交付前对照原成果，确认本次理解困难得到回应，文字与图形均未改变原意或判断边界。若所选表达反而增加理解负担，改用更简单的方式，不以篇幅、图形数量或形式完整代替讲清楚。
