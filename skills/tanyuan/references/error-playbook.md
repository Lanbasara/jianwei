# 失败后的研究路径

先读取响应里的 `error.hint`、`details` 和候选项。完整错误分类、退出码和重试语义由 `ty help errors` 提供；此处只讨论如何继续研究。

## 参数需要修正

按 `details.expected` 和对应 `ty describe <tool>` 修正。候选标的需匹配用户意图；不确定时向用户确认。参数错后原样重试没有意义，但修正后可以重新调用。

## 来源不可用或没有结果

先区分“请求失败”和“该来源在该范围没有数据”。空结果不能证明事件未发生，也不能证明所有来源都没有。记录已查来源与范围。

换源之前确认它是否覆盖同一指标、期间和市场。例如日线收盘价不能冒充盘中实时价；搜索摘要不能替代已核验的财务数据。通过 `ty tools` 和 `describe` 选择当前可用能力，避免依赖写死的备用工具表。

如果只有部分标的或来源成功，保留成功部分，单独列出缺失及原因。遇到限流按响应退避；遇到权限、额度问题先由用户处理配置。

## 原文与历史证据

网页只能拿到预览时，按该工具的返回字段继续阅读或定位本地全文；“预览结束”不等于“原文结束”。响应缓存与正文存档可能不同，刷新方式查看工具描述。

新闻/RSS 历史窗口不足时，按 `news-recovery.md` 的路径寻找公告或官方归档；查不到时说明范围和限制。

## 停止条件

出现上游结构变化时不使用本次结果。找不到同口径替代来源时保留未知，不为了交付一个数字而换定义。产品内部错误应提供版本和脱敏后的复现方式，不把密钥或含凭据的 URL 放入报告。
