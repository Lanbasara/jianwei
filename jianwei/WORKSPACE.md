# 工作区约定

工作区保存持续积累的研究、投资背景、建议与用户选择。使用用户指定的目录；未指定时使用当前任务目录，保持工作产物与已安装的插件分开。

日期目录 `YYYY-MM-DD/` 形成时间线，按实际发生的工作创建内容。研究及需要底稿的分析使用自己的 case 目录：`YYYY-MM-DD/case-001/`。日期取 case 建立的日期，编号在当天目录内递增。继续同一项研究时沿用已有目录；后来发生的重要判断变化，在新日期留下说明并链接旧依据，保留当时的判断。

接续既有判断时，说明是否发生实质变化及原因，例如新事实、价格与估值变化、用户目标或约束变化、原有推理的修正。措辞变化不等于判断变化；没有新事实也可以纠正旧推理。依据不足以比较时保留未知，不把缺少更新当作已经证实未变。

每个 case 的入口和产物按以下方式放置：

- `case.md`：用标题和简短说明介绍分析的问题，并链接实际形成的主要成果。
- `work/`：本次分析的工作空间，保存底稿、资料、计算和中间文件，内部按问题需要组织。
- `report.html`：研究的最终 HTML 研报，在成稿后提供。

日期目录中另有两种按需形成的记录，无需为每个日期预建文件：

- `portfolio.md`：用户提供的持仓快照，以及相关目标、约束和补充说明。新建或更新时，读取[持仓快照的写法](references/portfolio-snapshot.md)，按实际已知信息记录；分析判断放在相应成果中。
- `decision.md`：当日围绕投资选择形成的建议，以及用户实际表达的决定、理由或执行情况。用标题区分不同选择，明确建议与用户表达的归属、条件和时点，并链接具体研究或分析依据。只有建议或只有用户决定也可以记录；后来作出的决定或修订留在后来日期，并链接之前的记录。

没有新的持仓快照，表示没有更新记录；最近一次快照仍是带有原时点的已知背景，不代表现状已经核实。建议的适用性取决于原来的条件，用户决定与执行是历史事件；没有记录不意味着没有发生，也不能据建议推断用户已执行或更新持仓。

新任务可以先搜索 case 的说明与相关日期记录，再按当前问题逐步阅读正文和依据。日期帮助了解先后，标题和说明帮助判断相关性；同日内容不自动相关。引用持仓或旧判断时指向所用的具体记录，区分记录日期与资料时点，按需补足会影响当前任务的信息。

一份成果保留在一个主要位置，其他记录通过相对链接引用；必要的摘要保留原条件与重要限制。让后来者能够从入口找到成果、追查依据并理解当时的选择，不要求阅读整段历史。
