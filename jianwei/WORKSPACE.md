# 工作区约定

工作区保存分析成果、投资背景、建议与用户表达及其当时依据。已完成的 case 是可查询的档案，不因保存位置、日期较新或反复引用而成为当前事实、现行策略或必须接续的任务。新任务由用户当前问题决定范围，按需复用材料与方法，核对关键依据对本次问题是否成立。

使用用户指定的目录；未指定时使用当前任务目录，保持工作产物与已安装的插件分开。日期目录 `YYYY-MM-DD/` 形成时间线，按实际发生的工作创建内容。研究、组合分析与复盘等独立分析使用 case 目录：`YYYY-MM-DD/case-001/`。日期取 case 建立的日期，编号在当天目录内递增。以分析任务而非研究对象为单位保存成果：原任务的讨论、补证与澄清沿用已有目录，已完成后提出的新问题按本次任务组织；较大任务中的局部分析可以放在该任务的 case，简短问答无需仅因调用了 skill 就新建文件。

比较既往与本次判断时，说明实质变化及原因，例如新事实、价格与估值变化、用户目标或约束变化、原有推理的修正。没有新事实也可以纠正旧推理；依据不足以比较时保留未知，不把缺少更新当作已经证实未变。重要判断变化在新日期留下说明并链接旧依据，保留当时语境，不为一致而改写旧稿。

每个 case 的入口和产物按以下方式放置：

- `case.md`：用标题和简短说明介绍本次问题、分析截至时点与已完成范围，并链接实际形成的主要成果。尚存缺口保留为当时的限制，由后续问题决定是否继续调查。
- `work/`：本次分析的工作空间，保存底稿、资料、计算和中间文件，内部按问题需要组织。
- `report.html`：本 case 已有成果的 HTML 成稿，按需生成。

日期目录中另有两种按需形成的记录，无需为每个日期预建文件：

- `portfolio.md`：用户提供的持仓快照，以及相关目标、约束和补充说明。新建或更新时，读取[持仓快照的写法](references/portfolio-snapshot.md)，按实际已知信息记录；分析判断放在相应成果中。
- `decision.md`：当日围绕投资选择形成的建议，以及用户实际表达的决定、理由或执行情况。用标题区分不同选择，明确建议与用户表达的归属、条件和时点，并链接具体研究或分析依据。只有建议或只有用户决定也可以记录；后来作出的决定或修订留在后来日期，并链接之前的记录。

HTML 成稿沿用所承接成果的位置：case 内默认使用 `report.html`，由 `case.md` 链接；承接 `decision.md` 中的建议时，在该日期目录使用能区分主题的 HTML 文件名，并从对应建议条目链接。已有不同成稿时，另取能区分内容的文件名。成稿说明所承接的具体成果及其时点、条件，已有文件通过链接引用；原始成果和记录继续保留，编辑成稿不改变专业判断或用户行为记录。用户直接提供的材料或对话成果，按指定位置交付；未指定时保存在当前任务目录，无需仅为成稿另建分析 case。

没有新的持仓快照，表示没有更新记录；最近一次快照仍是带有原时点的已知背景，不代表现状已经核实。建议的适用性取决于原来的条件，用户决定与执行是历史事件；没有记录不意味着没有发生，也不能据建议推断用户已执行或更新持仓。

查找材料时，可以先搜索 case 的说明与相关日期记录，再逐步阅读正文和依据。日期帮助了解先后，标题和说明帮助判断相关性；同日内容不自动相关。引用持仓或旧判断时指向所用的具体记录，区分记录日期与资料时点，按需补足会影响当前任务的信息。

委派或安排后续研究时，交代要回答的问题、所需能力与资料入口、资料和判断的时点，以及用户授权范围。本次预测、阈值与建议作为待检验的依据，不写成后续必须维持的结论或禁止改判的规则。接手时按该次任务核对关键前提；任务已保存或已到触发时间，不表示前提已经重新证实。用户明确要求核验固定规则时保留该范围，不自行扩成策略重估。

个案发现和改进建议保留在对应成果中，不自动提炼进每次默认读取的经验文件、修改 agent 指导规则或建立用户永久偏好。

一份成果保留在一个主要位置，其他记录通过相对链接引用；必要的摘要保留原条件与重要限制。让后来者能够从入口找到成果、追查依据并理解当时的选择，不要求阅读整段历史。
