# Jianwei 设置

帮助用户把当前 Jianwei 安装副本准备到可运行状态。保持用户当前工作目录；从本文件位置向上两级定位插件根目录，不要求用户查找宿主的插件缓存路径。

## 先检查，再修改

先调用 `python3 "<插件根>/scripts/setup.py" --status` 做离线检查；它只输出 Python 状态以及四个凭据名称是否已配置，不输出值。再调用同一插件内 `skills/tanyuan/bin/ty --version`。已可运行时说明当前环境正常；除非用户还要检查凭据或数据源，不重复初始化。

需要初始化时，先说明默认只在当前 Jianwei 安装副本的 `.runtime/` 内创建隔离 Python 环境、配置模板和缓存，不写当前项目、不修改全局 PATH，也不安装系统 Python。然后调用：

```bash
python3 "<插件根>/scripts/setup.py"
```

用户已有满足要求的 Python 时可传 `--python`；用户已有私密配置文件时可传 `--env-file`。路径必须来自用户或可靠的本地发现，不猜测路径。默认凭据文件属于当前插件副本，升级或卸载可能移除；在用户填写付费凭据前主动说明这一点，并优先提供 `--env-file` 外置选择。

需要改用其他运行目录时，只接受用户明确选择的绝对路径，并用 `JIANWEI_HOME` 同时运行初始化和后续命令。说明新会话也必须由宿主持续提供同一变量，否则会回到插件内 `.runtime/`；未经请求不编辑 shell profile 或宿主配置。

## 凭据

全功能需要用户自行购买或申请并配置 `TUSHARE_TOKEN`、`TAVILY_API_KEY`、`DEEPSEEK_API_KEY`，并为 SEC 请求填写联系标识 `SEC_CONTACT`；数据源账户还必须具有相应接口权限。不替用户注册、购买、充值或绕过权限。

不要要求用户把密钥粘贴到聊天中，不读取或输出密钥值。让用户在自己的编辑器中填写初始化结果指向的文件，或用 `--env-file` 选择已有文件。检查时只报告每个名称“已配置”或“未配置”。

## 处理失败

- 找不到 `python3` 或版本低于 3.10：说明最低版本要求，让用户自行选择安装方式；未经要求不调用系统包管理器。
- 安装依赖失败：保留原始错误摘要，区分网络、证书、代理、磁盘空间和 PyPI 不可达；给出可重试命令，不盲目重复。
- `--python` 校验失败：说明它必须是可执行的 Python 3.10+，并精确安装当前 `requirements.txt` 中的版本。
- 插件目录不可写：不要自动改写到系统应用目录、用户项目或其他猜测位置。解释原因，请用户提供一个可写的绝对目录作为 `JIANWEI_HOME`。
- 出现 `.setup-lock`：先确认没有初始化进程仍在运行；只有用户明确同意后才移除遗留锁。
- 缺少凭据或权限：指出具体变量或服务以及购买/申请方向，不把鉴权失败描述成无数据。

失败后不得声称安装完成。修正原因后重新运行最小受影响检查。

## 完成检查

初始化成功后再次运行 `setup.py --status`、`ty --version` 和 `ty tools`，确认依赖、四项凭据名称、CLI 与能力清单状态。只有用户明确同意联网和潜在计费后才运行 `ty doctor` 或真实数据查询；`doctor` 未覆盖的服务仍需分别做最小查询。逐项报告 Tushare、Tavily、DeepSeek 与 SEC 的成功、缺少凭据、权限不足和上游失败，不用部分成功代表“全功能已就绪”。
