# Tanyuan QA（不交付）

这里存放确定性离线回归和冻结的历史评测材料。产品目录和交付包不能依赖这里。

- `tests/`：CLI 契约、合成输入行为、安装/路径/配置/交付边界测试。
- `evals/`：已经曝光的历史题库、规则判分器与判分原语自测。历史成绩、模拟答案和联网运行产物不在本仓保留。
- 第三方 raw 证据只保存在本机，可能受再分发限制，不进入 Git 或产品包。需要证据验证时，显式将 `JIANWEI_QA_HOME` 设为本机 golden 根目录；相对路径、缺失目录和越界链接都会被拒绝。

产品修改只修改产品与通用回归测试。题面、真值、判据的改动必须独立说明来源和理由，不以现有实现能否拿高分决定正确答案。`frozen.json` 记录本轮保留的题库和证据哈希，`check_frozen.py` 检测意外改写；它是漂移检测，不是防恶意篡改的权限机制。

对用户能力的验收需要全新工作区与受限文件访问：只挂载交付包、用户任务和输出目录，不挂载这个仓、题库、历史报告或包含答案的历史上下文。仅换一个会话、仅换 cwd 或用 subprocess 启动不能保证隔离。本仓没有实现操作系统沙箱管理器。

AI/质量评测只能在本地显式运行，属于非门禁诊断；不得阻塞 PR、发布、安装或升级。普通离线单元测试不需要 `JIANWEI_QA_HOME`。

建议测试顺序：先记录预期行为 → 在未修改本体上复现 → 做通用机制修复 → 跑既有回归和未使用过的输入。题目暴露后归入回归集，新的独立验收题应由不改本体的维护者持有。

## 已知质量债

此轮处理交付、运行位置和污染，不宣称修复此前审查中的全部数据正确性缺陷：entity.resolve 市场/截断歧义、行业层级失败兜底、SEC 索引失败与日期溯源等仍需独立修复与验证。规则判分器的引用、否定与多指标判定也仍有缺陷。不要把清洁交付等同于金融数据准确性验收。
