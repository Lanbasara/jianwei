# 证据规则(写结论前必读)

> 目标:任何进入研报/结论的数字,都能回答「谁说的、什么时候的、能不能回查」。

## 1. 四级证据

| 等级 | 是什么 | 例子 | 可以怎么用 |
|---|---|---|---|
| **L0** | 一手法定披露 / 交易所原始文件 | 巨潮公告 PDF、上交所/深交所文件、SEC filing | 可直接作为事实引用,给 PDF/详情页链接 |
| **L1** | 结构化专业数据 | 行情、K 线、财报三表、LPR/宏观、申万行业指数 | 可引用,必须带 source + 相关业务日期 + 单位 |
| **L2** | 有署名的新闻/研报/舆情 | 财联社、华尔街见闻、东财研报、央视新闻 | 只做事件线索与观点;其中的数字要回 L0/L1 |
| **L3** | 通用搜索 / 未署名聚合 | `search.web`、`fetch.url` 抓到的网页 | **只做发现**;不能作为数字来源,不能单独支撑结论 |

**硬规则:L2/L3 的数字不得单独成为结论。** 若必须引用,写「据 X 报道(未核验)」并给出核验路径。

## 2. 时间与历史可见性

- `observed_at` 是这份数据实际取得的时间;缓存和正文续读保持它不变。
- `as_of` 仅在能明确表达数据快照时点时提供,否则为空。它不是查询时间,也不保证历史可得性。
- 使用记录中的 `trade_date`、`report_period`、`ann_date`、报价时间或发布日期解释数字;不同日期含义不能互换。
- 报告期不等于披露日。有公告日也不证明当前返回版本当时已经可见;未保存修订历史时不能承诺严格 PIT。
- 查询范围看 `query_window`,实际返回跨度看 `data_span` 或记录日期;不要把请求边界当成数据覆盖证明。

## 3. 单位与口径

先确认本次响应与工具描述中的单位及适用范围,来源说明见 `references/number-style.md`。

1. 工具可能返回原值或已声明的换算值,不能假设所有工具都不换算。
2. 比较前统一指标、币种、期间和单位;展示精度由输出场景决定。
3. 单位存疑时回查来源。量级自检只能发现异常,不能证明语义;无法确认就披露未知。

## 4. 引用格式(给上层报告用)

每条数据引用应包含:

```
值 + 单位 + 相关业务日期 + 来源 + 可回查链接(或工具调用参数)
引用格式:标的 + 指标 + 数值及单位 + 对应业务日期 + 来源与工具名。
模板:《<公告标题>》(<来源>,<响应中的披露日期>,L0):<响应中的原文 URL>
```

- 能回查的才算证据:URL / 公告 ID / 工具 + 参数。
- 研报只可引用「机构 + 日期 + 标题 + 评级/预测值」,不得大段复制正文;不得再分发 PDF。

## 5. 多源冲突怎么办

1. **不要静默择一。** 列出两个值、各自来源与业务日期。
2. 先查口径差异(复权/单位/时点/总市值 vs 流通市值)。
3. 口径相同仍冲突 → 以 L0 > L1 的优先级判断,并在结论里注明冲突。
4. 冲突未解决时,该数字只能作「区间/存疑」表述,不能进结论。

## 6. 数字自检(写进结论前跑一遍)

- [ ] 这个数字来自 L0/L1 工具,而不是搜索摘要?
- [ ] 日期含义写清楚了?
- [ ] 单位/复权口径写清楚了?
- [ ] 换一个源能对上吗(Tushare vs 腾讯 vs 新浪)?
- [ ] 如果是比率/增速,分子分母同期同口径吗?
- [ ] 有没有把「报告期末」当成「当时可见」?
